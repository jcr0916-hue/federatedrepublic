## 2. Submission and publication workflow

**Submit:** Each agent chooses a clear kind: `idea` (short seed), `report` (observational/source analysis), `government-proposal` (hypothetical institutional mechanism), `character-development` (private arc possibility), or `article-draft` (prose candidate). If the server's `kind` enumeration does not implement these editorial labels, submit as a supported `report`/proposal and put the requested type in the body; **do not pretend the server schema changed**. Every submission contains (a) 1–2 sentence pitch, (b) jurisdiction and author/desk, (c) published citations/source IDs, (d) exactly what is established versus proposed/invented, (e) constitutional and clock implications, (f) effects on other desks and whether consultation is requested, (g) intended format/outlet, (h) urgency and next decision requested. Label disputed facts. Do not mint an NRS/worldSeq or treat unapproved names, quotes, vote counts or acts as facts.

**Triage:** Central Editor maintains an editorial decision log distinct from immutable original proposals. On intake check duplication, legal jurisdiction, approved status of cited events, character collisions, physical geography, timeline, and whether the idea belongs in a local story, opinion or formal government record. Agent sees original PROPOSED status in the existing legacy interface even after private editorial overlay; do not promise that an agent can read the Editor's private disposition. Communicate revision/hold decisions through the approved agent channel separately.

**Decisions:**
- **ACCEPT FOR DEVELOPMENT:** Quality and continuity sufficient to develop, not a published or governmental approval. State precise deliverable, responsible agent, review conditions and possible collaborators.
- **HOLD:** Preserve the proposal without action; note blocking source, timing, duplicate beat or unresolved constitutional question, and condition to reopen. No forced deadline.
- **REVISION REQUESTED:** Return a numbered editorial change list and any source questions; agent resubmits a new revision referencing original key, without altering historical proposal or claiming prior status as canon.
- **REJECT:** Log concise grounds (contradicts canon, wrong institution, low value or duplicates); retain auditable submission and discourage repetitive resubmission unless the premise changes.

**Publish lane (separate):** Central Editor checks canonical published references and repository `STORY-BIBLE`, `STORY-STATUS`, `constitution_data.json` and clock registries, settles all proposed-fact annotations, approves names/quotes/official-mechanism assumptions, then prepares **a fresh content feature branch**. Preview world helper/sequence/metadata first; reserve no sequence numbers for editorial submissions. Run World/publishing validation and independent continuity review, open a **draft PR** with its own `AGENTS.md` branch handoff, wait for Presidential approval of exact content and merge. No agent has direct GitHub write or production deploy privilege. Accepted but unmerged material remains noncanonical; merge does not independently verify website deployment. Review events must not be conflated with publication.

**Weekly editor queue:** Record submission key, desk/type, published-source references, decision, reviewer, revision pointer, canon risk and next review trigger. Keep character ideas and policy proposals in the *planning* lane until actually published. If story crosses jurisdictions, obtain both desks' observations; final resolution stays with Central Editor and President, not the Federal agent.

## 3. Cadence and escalation

**Ordinary pace:** Each active geographic or Federal desk checks its published source packet **twice per week** (suggest Wednesday and Saturday) and may send **one concise digest per week** when it has worthwhile changes; zero submissions is a valid healthy week. Agent can submit worthwhile local color/story drafts asynchronously without a numerical target. Central Editor reviews intake **Monday/Thursday** or on a major event, publishes no daily quota and avoids repeated no-change pings. Existing local documentation or useful fiction takes priority over mechanical reporting.

**Developing storyline:** An actual newly published record, election filing, constitutional deadline, public authority decision or meaningful cross-desk consequence can trigger an extra short report **within one editorial review cycle**, generally within 24–48 real-world hours when feasible. It should summarize what's changed, cite exact source, identify affected desks and propose up to two follow-ups. A mere rumor, agent-generated proposal or editorial brainstorm cannot trigger an artificial emergency. Central Editor decides whether to request more frequent updates and must explicitly end escalation after the beat stabilizes (default review at the next twice-weekly intake). No autonomous daily posting loops, imaginary events, or synchronized manufactured crises.

**Metrics:** Track useful original leads, accepted/revised/held ratio, duplicate rate, source/continuity errors and agent burden rather than raw story counts. Leave weekends quiet when sources are quiet.
