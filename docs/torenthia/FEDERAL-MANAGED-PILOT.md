# Managed Federal pilot

The managed pilot takes one reviewed Federal revision assignment and proposes one shareable update to the Federal working notes. The first exercise uses synthetic GitHub and R2 responses. The [editorial trial in #324](https://github.com/jcr0916-hue/federatedrepublic/pull/324) supplies the workflow this exercise models.

## Run the fixture

Use Node 24 from the repository root.

```sh
node --test --test-timeout=10000 scripts/newsroom/*.test.mjs
node scripts/newsroom/federal-dry-run.mjs
```

The exercise simulates one exact receipt read, one notes commit on an open draft, and an exact replay with the same commit SHA. The fixture signs short-lived grants with an ephemeral key and enables Federal in a copy of the roster. The checked-in roster parks all four desks. The preview makes zero external requests, zero model calls, and spends zero cents. `LITELLM_PRO_MODEL` and `LITELLM_FLASH_MODEL` are placeholders pending Constitution 19.

## Trusted runner and review

- Run [the managed pilot](../../scripts/newsroom/managed-federal.mjs) in the trusted runner. Give the model only the verified assignment and reviewed public sources. The assignment contains the receipt UUID, decision UUID and editorial task. The runner retains the authenticated grant and GitHub and R2 clients. GitHub is public, including draft branches. For the first supervised run, the editor checks the exact note is shareable before handing it to the writer.
- A dispatcher in the trusted environment signs each Federal job with Ed25519. Pass the writer only the dispatcher's public key and the signed grant. A grant has the format `base64url(JSON).base64url(signature)`, with the signature over the ASCII encoded JSON segment. Its fields are `audience` (`jcr0916-hue/federatedrepublic:managed-federal:v1`), `agentId` (`federal`), `issuedAt` and `expiresAt` (UTC epoch seconds, at most five minutes apart), `policyHead` (protected main commit), `expectedHead` (notes branch commit), `pullRequest` (the draft's number), `receiptId` and `decisionId` (UUIDs).
- The writer reads the roster and the ledger from the `main` commit pinned in the grant and checks the live protected head before the R2 read and GitHub write. Both switches must permit the authenticated agent. A moved protected head invalidates the grant, so a paused desk cannot use a roster from its PR. The recheck and the GitHub write are separate requests. An operator pausing a live pilot must also stop its in-flight job and reconcile any pending response.
- The runner reads the original R2 object by the single exact key from the current `REVISION_REQUESTED` decision's ledger entry. It checks the receipt hash and desk against that entry and passes only the assignment to the model. The read-only bridge receives `getObject(key, { signal })` and returns a fetch `Response` for the original object. Honor the signal through body consumption. Raw receipt text, source references and legacy status overlays stay out of the public notes and model inputs.
- An editor stages a same-repository draft from `agent-notes/federal` to `main` with one shareable change to the existing Federal `notes.md`. The proposed update may replace only that exact nonexecutable file. The writer checks the signed PR, both refs, the immutable diff and the expected head. GitHub commits the single change with `expectedHeadOid`. The writer rechecks the resulting commit, content and draft. A fresh note on a moved draft requires a new reviewed head. After a lost response, retry the exact authorized request while its grant is valid. The committed content, parent and job fingerprint determine whether it already applied. [GitHub commit mutation](https://docs.github.com/en/graphql/reference/commits#createcommitonbranch)
- The PR stays a draft throughout the managed run. GitHub controls the later review of the exact diff. The editor handles review and the authorized maintainer handles any merge through the usual process. The writer can update the note on the pinned branch and read the draft state.

## Provisioning specification for review

- Install a dedicated GitHub App on `jcr0916-hue/federatedrepublic` only, with Contents write, Pull requests read and implicit Metadata read. The App's private key and short-lived, repository-scoped installation token belong to the trusted runner. Limit the runner to the fixed GitHub API origin. Use a separate signing key for Federal job grants. Stage the branch and draft using the editor's existing permissions. [Installation token scoping](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app)
- Verify that active rules on `main` require one or more approving reviews, dismissal of stale approvals, the **World publishing check**, and protection from force pushes and deletion. Confirm the required check comes from GitHub Actions and the App has no bypass. The writer reads effective rules with Metadata permission. A repository administrator verifies rule sources and bypass actors during provisioning. The editor also checks the path-filtered **Newsroom workspace check** on the draft. [Effective branch rules](https://docs.github.com/en/rest/repos/rules#get-rules-for-a-branch) · [GitHub rules](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets)
- Bind the inbox bridge to the existing newsroom bucket using a separately approved bucket-scoped Object Read Only credential. The runner needs one exact object GET. Its code has no R2 write or delete operation. The legacy TypingMind desk credentials and submit route operate under their own controls. Managed roster switches apply only to this runner. [R2 API token scope](https://developers.cloudflare.com/r2/api/tokens/)
- Set the paid-run rate and usage limits after Constitution 19 settles the provider and model aliases. Reuse the unified-agent prototype's reviewed source packets and saved work-order receipts when integrating model calls. Verify hard limits on calls, tokens, time and spend, including upstream retries and fallback. Reserve the session's budget and claim its run durably before a paid invocation. The fixture displays the roster's proposed limits for review.
