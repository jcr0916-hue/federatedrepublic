# Torenthia newsroom operations

GitHub holds the agent workspaces, editorial decisions and reviewed publication changes. Agents use published `main`, the [project source hierarchy](../../PROJECT-SOURCES.md) and their own desk workspace. The existing Cloudflare R2 newsroom remains the intake for reports. The Central Editor uses the Cloudflare connector to read the inbox and GitHub branches to record decisions and feedback. The President approves publication through the [existing review and merge process](PUBLISHING.md).

## Phase 1 controls

- [Roster](agents/roster.json) is the managed runtime configuration. It starts with the four independently verified TypingMind desks, Federal, Korda, Varek and Corindal. [Editorial status](EDITORIAL-CURRENT-STATUS.md) records qualifications and other desks.
- Each `agents/<id>/workspace/` has an editor-owned `desk.md` for assignments and story tracking, and a `notes.md` for shareable agent checkpoints. Existing source packets, qualification records and candidate files live alongside the workspace.
- `automationEnabled: false` stops every managed agent. Each `enabled: false` stops that agent. The planner and the submission and notes policy use the same roster. Controls take effect in a managed runtime once it reads them from the trusted ref. The four legacy TypingMind connections still use their original desk credentials. They stay under their current manual controls until a separately approved cutover. Set the desired toggle before handing an identity to the managed runner.
- The dry-run planner uses fixed UTC weekly slots. The pilot defaults reserve at most one agent and five cents per slot, with at most two model calls, 16,000 input tokens, 4,096 output tokens and 120 seconds per agent run. These are proposed limits for review. The two model references correspond to the existing LiteLLM Pro and Flash aliases. The preview uses zero model calls. Provider billing limits are part of the managed pilot.
- GitHub Actions checks PR changes and supports a manual planning preview once the workflow is present on the default branch. It has read-only permissions, cancels superseded checks in the same group and times out after five minutes. The workflow contains no scheduled trigger, write jobs or credential bindings.
- GitHub is public. Commit shareable notes, assignments and ledger metadata only. Keep unpublished drafts requiring confidentiality, raw R2 objects, connection settings and credentials out of the repository, including feature branches and PRs.

From the repository root, use Node 24 for a credential-free check and dry run.

```sh
node --test --test-timeout=10000 scripts/newsroom/*.test.mjs
node scripts/newsroom/cli.mjs validate
node scripts/newsroom/cli.mjs plan 2026-11-16T16:00:00Z
```

## Controlled writes and rollout

1. **Central Editor trial.** With the roster parked, use an existing synthetic R2 receipt. Prepare one decision and a shareable revision assignment on a GitHub editorial branch. Retry the same receipt and decision, confirm one ledger entry, and review the PR diff. Use the direct Cloudflare R2 connection for the exact read. The isolated OAuth experiment in [PR #322](https://github.com/jcr0916-hue/federatedrepublic/pull/322) remains outside this workflow.
2. **Managed Federal pilot.** Reuse the existing unified-agent Pro/Flash runner and published-source packet logic when connecting the scheduler. The prototype is a local source for reuse. GitHub holds the durable editorial state. Have trusted workflow code load and validate the current roster from the protected default branch, bind the authenticated agent ID to the job and mint a short-lived GitHub App token only in the writer. Install the App on the newsroom repository with Contents write and implicit Metadata read. Add Pull requests write only if this same trusted writer must open PRs. Protect `main` with required review and checks and keep the App off its bypass list. Keep the token, arbitrary shell access and raw GitHub write tools out of the agent session.
3. **Notes.** Run `prepareNoteChange` in the trusted writer, using the trusted branch head and authenticated job identity. It accepts one UTF-8 file at the roster’s exact `notes.md` path and derives `agent-notes/<id>`. The writer must confirm that destination contains a regular file, write exactly that file as data with an expected-head check, and open or update an editorially reviewed PR. Use the GitHub API’s expected-head commit operation or an equivalent compare-and-set. Verify the resulting diff before review. GitHub folder names alone confer no permissions. Phase 1 tests the policy and emits a proposed change. Connecting an App and writer is the pilot work. [GitHub installation tokens](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app) · [Repository rules](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets)
4. **Submissions.** Keep existing R2 intake. Bind each managed identity to its own newsroom desk in the trusted client holding the desk credential. Re-read the protected roster immediately before each write and check the mapped desk against the returned receipt. With the legacy Worker, a lost response can follow a successful put and the Worker assigns a fresh UUID per call. Reconcile an ambiguous result against the inbox before retrying. When a desk moves to managed operation, explicitly address the manual TypingMind path and any already-issued standalone credential. A retained legacy credential can still submit outside this policy. Strong runtime disable requires the managed path to hold the credential exclusively and the ingress to reject bypasses.
5. **Scheduling.** Start with a manual, single-desk dry run against fixtures. Before allowing paid runs, reserve a per-slot and daily budget, verify actual rates and upstream retry/fallback behavior, and enforce configured calls, tokens, timeouts and spend before invoking a model. Serialize writes by agent and claim a stable `agentId/slot` durably to prevent duplicate spend on reruns. Re-read the live toggles before any external side effect and cancel in-flight work when pausing. Stagger UTC slots across the eventual roster. An agent deferred by the slot limit needs a different slot in the roster. Enable a scheduled trigger only after an approved Federal pilot and cost review. [GitHub Actions concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)

## Add or pause a desk

- Add a unique ID with its jurisdiction or specialist desk name, weekly UTC slot, named provider and alias references, and bounded budget. Create its `workspace/desk.md` and `workspace/notes.md` under the existing agent directory. Keep new entries disabled and use `inboxDesk: null` until a distinct server-scoped newsroom desk is verified. The current live Worker recognizes four desk credentials. Onboarding more desks requires approved changes to that existing ingress.
- Set `enabled: false` to pause one managed desk and retain its row, inbox identity and ledger history. Set `automationEnabled: false` to pause every managed desk. Review the protected-ref change and cancel active jobs when operating the live runtime. Keep a retired identity disabled so older receipts remain readable.

## R2 retention proposal

Readback on November 14 showed only the default rule to abort incomplete multipart uploads. Keep the `submissions/`, `status/` and `reviews/` prefixes outside blanket expiry rules. Start the proposed 30-day retention window once an `ARCHIVED` disposition and its audit record are merged and the original receipt has been verified at an immutable GitHub archive commit. Use restricted access for unpublished content that cannot go in this public repository.

For a separately approved cleanup, generate a read-only list of exact keys from merged ledger entries with a verified archive and elapsed retention window. Check the original payload, the stored receipt hash, associated review history and the current disposition. Keep pending, held, revision-requested, unarchived or unverifiable objects out of the list. Approve the candidate list, recheck the payload and disposition before any later removal, and preserve the cleanup result in GitHub. A prefix lifecycle rule could apply later to copies in a dedicated processed prefix. It would leave the original `submissions/` objects in place. [R2 object lifecycle rules](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)
