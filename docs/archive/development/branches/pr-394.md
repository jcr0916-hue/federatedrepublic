# Branch history — newsroom/triage-never-unsorted

**PR:** [#394](https://github.com/jcr0916-hue/federatedrepublic/pull/394)
**Status:** proposed (draft; awaiting John)

## Purpose
The desk editor's triage left every filing "unsorted" on Nov 20, 23 and 24 (Nov 19 and 22 sorted). The model's summary in those reports described the filings correctly, so its per-filing list was lost between the reply and the report. Make the sort resilient and make any remaining failure visible.

## Shipped in this PR (on merge)
- `api/_newsroom-triage.js`: lenient matching of the model's list to inbox keys (exact key, filing id, unambiguous title; alternate list names; route spelling); one retry for the whole set when filings are missing; declared-track fallback (records to `records`, ideas to `idea-board`, canon stays `unsorted`); a report note giving the count sorted and the stray keys returned. New exports `matchRows` and `declaredRoute`.
- `scripts/newsroom-triage.test.mjs`: five new tests and one updated expectation (a skipped record now follows its declared track).
- `docs/torenthia/NEWSROOM.md`: the desk editor paragraph describes the matching, retry and fallback.

## Decisions
- The root cause is not confirmed (the raw model reply is not kept), so the fix covers each plausible failure and the note records the evidence next time.
- Canon filings stay `unsorted` when the model gives no ranking: ranking is a judgment, and the desk editor decides nothing and discards nothing.
- Retry is one call and whole-set, so ranks stay consistent across the day's filings. The cost is about a cent, only on a bad day.
- Prompt, model (Claude Haiku 5.5) and output limit unchanged.

## Results and verification
`npm run test:newsroom-run` 49 of 49 and `npm run test:newsroom-inbox` 24 of 24 pass. The full publish check was not run; the change is limited to the triage module, its tests and one doc paragraph.

## Known limitations
If the model's reply has no usable list at all on a canon-heavy day, canon filings still arrive unsorted (now alongside a note saying why). Look at that note's stray keys, then consider keeping the raw reply in the report.
