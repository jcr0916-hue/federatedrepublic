## Purpose and changes
ChatGPT's optional `ui_locales` query parameter triggered `invalid_authorization_request` in the issuer's strict authorization-input allowlist. `workers/newsroom/src/issuer-candidate.ts` now accepts a single bounded locale hint and ignores it for authorization decisions; registered client, exact redirect, PKCE, issuer, audience, and scope checks remain strict. `workers/newsroom/test/issuer-candidate.test.ts` adds valid, malformed and duplicate-locale regression checks.

## Actual evidence
At source commit `b26673e0c0216e1dfe82625926207f760f2b8f08`, GitHub Actions Newsroom OAuth and World publishing workflows passed. A CI-built issuer candidate was manually deployed to **isolated** `newsroom-strict-issuer-candidate`, with all 12 Cloudflare bindings intact. Hosted ChatGPT plugin 'Torenthia OAuth Verification 04' subsequently completed actual authorization and code exchange (`/token` HTTP 200). This establishes real hosted compatibility; the final read path was verified downstream after PR #308 resource deployment. The hosted request's locale parameter is not separately recorded in raw logs for confidentiality.

## Preserve / do not repeat
An earlier failure came from a mismatch between the ChatGPT client secret and Cloudflare's SHA-256 binding; verified separately using an invalid refresh grant returning `invalid_grant` (credentials accepted). Do not copy OAuth secrets via a terminal command that overwrites the clipboard. Avoid re-creating Verification 04 solely to re-test authorization.
