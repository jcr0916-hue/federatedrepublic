# Branch history — feat/states-map-activity

**PR:** [#375](https://github.com/jcr0916-hue/federatedrepublic/pull/375) (draft)

## Purpose
John's direction (Nov 21, 2026): the Torenthia page carries too much, "pressure points" are too many, so keep the map on the States page, put the national flag on the main Torenthia page, and on the States map give each area one point that lights when there is new content about it, staying lit about three days, as a way to find what is new without another block of reading.

## What is in it (shipped when merged)
- **Torenthia page** (`torenthia.html`): the hero map and its "Current pressure points" line are replaced by the Four Founders flag (`flags/torenthia-four-founders.svg`) with a link to the flag's story in the first-twelve-years scenario. The map overlay script and its CSS are removed.
- **States page** (`republic-at-a-glance.html`): the ten hand-placed, always-pulsing topic dots (crisis, political, legal, diplomatic) are replaced by 16 points, one per State and Territory, positioned above each printed name. A point is lit while its newest non-routine record is under 72 hours old; the check runs in the reader's browser, so points fade without a rebuild. A "Lit now" row of buttons and the inspector list the new items (title, outlet, "N hours ago") with the earlier items below them, plus links to all records for the place and its profile. Reduced-motion and keyboard use are handled; on phones the points scale up so they stay tappable.
- **Publication ledger**: records had only an in-world month, no real time. `_data/worldPublished.json` maps every worldId to a real timestamp (backfilled from the commit that first added each file). `lib/world-published.mjs` holds the area list, the lit window and the `areaActivity` filter; `scripts/world-stamp.mjs` (`npm run world:stamp`) stamps missing records and `--check` (`npm run check:world-published`, inside `world:publish-check`) fails on a missing, malformed or orphaned entry. `docs/torenthia/PUBLISHING.md` gained the stamping step.
- Lighting rule: `worldJurisdictions` tags, excluding `worldMundane` records. The old `mapdots.js`/`mapEntries` (which matched `worldPlaces` and title aliases) and the dot CSS are removed.

## Tests and results
`scripts/world-published.test.mjs` (5 tests: areas equal the World jurisdictions and have map positions; newest-first, capped at three, mundane skipped; unstamped records never light; ledger check; every record stamped). `npm run world:publish-check` passed. Browser checks (Playwright, desktop and 390px phone): points render, selecting one fills the inspector, and with the clock moved forward the lit set shrinks (now: Caldenmere, Kelvant, Korda; +60h: Kelvant, Korda; +90h: none). Not checked on production before merge (deploys are `main` only).

## Decisions
- Real days (72 hours), not the in-world clock, because the lit state is a reader-facing "new" signal.
- Lit time is when the record first entered the repository, so a story merged days after it was drafted lights a little early. Rejected: stamping inside each of the 318 record files (touches every file and the authoring helpers).
- Points cover the 16 States and Territories only. The old Lake Varda, Valedon and Toren River dots (a lake, a neighbor and a river) are gone; Lake Varda coverage lights through the States it tags.
- Routine NRS filings never light a place.

## Known limitations / unresolved
- A record published without `npm run world:stamp` fails the publish check (by design) and would otherwise never light.
- The rest of the Torenthia page (carousel, Latest, Dispatches, States reporting) and The Record's routine-filings-first ordering are unchanged; proposed to John, not yet decided.
- `worldPlaces` front matter is now unused and left in place.
