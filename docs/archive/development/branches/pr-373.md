## Purpose
The stored annotation set for the Annotated Constitution (infrastructure in #372, voice rules in #371): all 177 provisions, generated ahead of time and checked, so readers get an instant annotation and no model call.

## What is in it
- `annotations.json`: 177 entries, each with the hash of the provision's current source packet (so any later change to the provision, its related provisions, its history entries or the packet logic marks it stale and sends it back to live generation), the text, the model and the date.
- `scripts/annotations-ingest.cjs`: merges staged annotations into the store; every block is checked (hash equals the current packet, word count equals the generator's, quality gate passes).
- `scripts/annotations-fetch-live.cjs`: fetches annotations from the public endpoint, applies the gate, and stages the passes.
- `api/_annotator-run.js` lint: length limit 575 words (the runtime contract's rewrite threshold; the prompt still targets 350–500), plus new checks for packet vocabulary ("lexical relative", "structural sibling", "defining provision", "explicit citation") and talk about the record ("the history records", "documented restructuring").

## How it was made
Generated by Sonnet 5 through the live endpoint and the protected generator relay (about $3 total). Output varies between calls, so failures were re-run until they passed the gate. A first run before the voice rules were live was discarded. 22 entries received small wording edits (internal jargon such as "defining provision" replaced with the section number or a plain description; a few phrases that talked about the record; one wrong claim in §2.9 about a "two-term structure" corrected to the 12-year limit; a typo in §12.6); those entries carry `edited: true`.

## Review
Every entry passes the gate: three paragraphs, 428–557 words (average 490), only real section numbers, no talk about sources, logs, dates or missing material. Two entries were read against the provision text (§12.6, §18.4) and matched; a spot check across the Articles is the remaining human step. About 20 entries still say plainly what a provision leaves to statute or does not cover; those describe the provision's actual limits, not the sources.

## Maintenance
After any constitution or change-log update: `npm run annotations:status`, then regenerate the stale ones (fetch script or relay), `node scripts/annotations-ingest.cjs <stage>`, and commit. Until regenerated, a stale provision is generated live as before.
