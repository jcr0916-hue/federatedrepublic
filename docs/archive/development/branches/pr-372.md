# Branch history — feat/annotator-stored-annotations

**PR:** [#372](https://github.com/jcr0916-hue/federatedrepublic/pull/372)

## Purpose
John asked for the annotations to be written ahead of time and stored, instead of generated by a model on every reader click. Reasons: per-reader cost drops to zero, quality can be reviewed before readers see it, and a stronger model can be used without a per-click bill. He had floated a cheaper drafter checked by Sonnet; the recommendation was that pre-generation makes that question moot (a full run is about $3).

## Shipped in this PR (infrastructure only; no annotations yet)
- `annotations.json` (empty store): `{ entries: { "§2.5": { hash, text, model, generatedAt } } }`.
- `api/_annotator-run.js`: stored lookup plus the live generator (moved out of `annotate.js`), and `annotationLint` (three paragraphs, 525-word limit, no talk about packets, logs, dates or absences, no unknown section numbers).
- `api/annotate.js`: serves the stored entry when its hash equals the hash of the provision's current source packet; otherwise generates live as before. Responses carry `source: "stored" | "live"`. `ANNOTATE_STORED=off` disables the store.
- `api/annotations-generate.js`: editor relay, answers only on protected `*.vercel.app` hosts (same gate as the inbox relay, no key). `?op=status` lists provisions needing generation; `?op=generate&nums=2.5,2.6` returns up to 8 annotations with hash and lint result. It writes nothing; the editor reviews and commits.
- `vercel.json`: build and route for the generator (300 s), data files included for both functions.
- `npm run annotations:status` reports fresh and stale counts and lint failures; a test requires every committed entry to pass the lint gate.
- Cache revision now also hashes `annotations.json` and the runner, so readers' cached annotations refresh when stored text changes.

## Staleness
The hash covers the provision text, its related provisions, its recorded history and the packet logic, so a change to any of them makes that provision fall back to live generation until regenerated. Staleness is reported, not blocking: it does not fail CI.
