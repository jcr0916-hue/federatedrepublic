# Branch history — fix/annotation-ai-footer

**PR:** [#374](https://github.com/jcr0916-hue/federatedrepublic/pull/374) (draft)

## Purpose
Annotations are now stored (#372, #373), so a reader's click no longer sends anything to a model. The "AI Feature* — how it works & your privacy" footer at the bottom of the annotation panel describes data handling that no longer happens for stored annotations. Remove it for them.

## What is in it (shipped when merged)
- `annotated.html`: the panel footer is hidden by default and shown only when `/api/annotate` returns `source: "live"` (a provision whose stored entry is stale falls back to live generation, which does send the provision text to the model). Live responses are cached in memory and `localStorage` with a leading `<!--live-->` marker so the footer returns with them on a repeat visit; unmarked cached entries (all earlier cache contents) show no footer.
- The line under the page title ("Click any provision title for AI-generated design rationale AI Feature*") is unchanged. The stored text is still written by an AI model, so that statement stays accurate.

## Checks
`npm run world:publish-check` passed. A Playwright run against a local server with `/api/annotate` mocked confirmed: stored hides the footer; live shows it; a cached live entry shows it again; a cached stored entry hides it. Not tested against production (the page has no branch preview; deploys are `main` only).

## Decisions
- Condition on `source` rather than delete outright, so the privacy notice remains where the live path still applies.
- Keep the page-level AI marker as the provenance line for stored text. Rejected: removing it (the text is AI-written).

## Known limitations / unresolved
- `ai-features.html` still describes the annotator as generating on each click; not reviewed in this PR.
- `CONSTITUTION_REVISION` does not hash `annotated.html`, so existing browsers keep cached annotations (no footer for them, which is correct for stored text).
